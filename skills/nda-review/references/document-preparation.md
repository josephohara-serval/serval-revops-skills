# Prepare the review copy

## Acquire the complete agreement

Use the attachment or source identified by the user. For a URL, inspect the actual agreement, including embedded documents, iframes, signature sections, and included exhibits. Use supplied credentials only for that access. Do not retain passwords in the skill, run record, or outgoing email.

For an email or document reference, resolve the intended agreement and version before conversion. Do not select an arbitrary search result. If the user supplies agreement text, generate the PDF from that text. A company name or description alone is not enough to invent agreement terms.

Preserve an existing PDF unchanged when it is complete and readable. If conversion is needed, prefer a native download or faithful export. If the source requires reconstruction, preserve the full text, clause order and numbering, defined terms, tables, exhibits, existing signature images, and blank form fields. Preserve existing field values as source content; do not fill in new company details, dates, or signatures. Do not submit the source form.

## Verify before sending

1. Identify the source title, counterparty, stated version/update date, and capture time. Keep the source URL when applicable. Label a reconstructed PDF as a review copy; put added provenance outside the contract text or in the cover email.
2. Compare extracted PDF text with the source section by section. Check numbers, punctuation, exclusions, and signature fields as well as clause coverage. Whitespace or line-wrap normalization is acceptable; substantive wording changes are not.
3. Render and inspect every page for missing text, clipped tables, bad page breaks, or omitted images. For scanned input, inspect the image pages; use OCR as an aid and flag uncertain text. Successful text extraction alone does not establish visual fidelity.
4. If completeness or material wording remains uncertain, report it and withhold submission until resolved or the user explicitly requests sending the identified incomplete copy. Do not silently repair legal terms.
5. Give the verified output a clear counterparty/version filename. Record the filename and SHA-256 hash when file access permits, or an immutable artifact/version identifier. Keep the exact artifact used for sending.

Use the host's available PDF tools or document skill. Do not assume ReportLab, a specific browser, or a Codex runtime path is installed. Keep the source and output in the user's private task storage, not in the shared skill or its examples. Do not change retention or delete originals without a request.
